# Issue-to-PR daemon: design notes

**Status:** Design discussion in progress. Andrew chose llxprt-code-rs as the first agent target. No implementation until Andrew explicitly says to build. Agreed requirements and proposals are separated here.

## What Andrew wants

Andrew currently sends issues to declared agents through llxprt-jefe, watches them reach PR, then sends another. Build a **small Rust daemon** to automate issue discovery, dispatch, and status through PR creation. Let the agents' existing rules and skills do the software work. V1 does not review, repair, merge, or loop on PR feedback. Andrew reports that PR actions are done and green at present, while LLxprt e2e is offline. For v1, a confirmed open PR counts even when it is a draft or checks are not green; report check status without gating completion.

- Configure issue sources across GitHub Projects and selection criteria: a ready-for-Luthor marker, no assignee, and an optional milestone. Claim by assigning the issue, then check that it no longer qualifies for discovery. Keep the ready marker; claiming does not remove it.
- Configure executable, arguments, prompt, working directories, and relevant GitHub projects/repositories. Start by testing llxprt-code-rs headless mode; do not hardcode a list of agent CLIs or implement their workflows in the daemon.
- Limit simultaneous agents, for example to five. Show whether each is working, silent, dead, or in need of attention, with useful logs.
- Continue an interrupted task, such as issue 10. Pause one troublesome task while others proceed.
- Create **daemon-owned git worktrees**, separate from jefe's directories and worktrees. This is an independent system.

## V1 operation: agreed scope and remaining proposals

Issue sources may span multiple Projects and repositories. Start testing with one repository on macOS, but support Linux too. Use a local CLI for controls. A source command or adapter is proposed to yield issues with tracker repository, issue number, and URL after applying the configured Project, ready marker, no-assignee, and optional milestone criteria. Do not assume `gh issue list` alone enforces Project membership or saved-view filters. Configuration maps each tracker repository to a code checkout and daemon worktree root. For a new issue: record a task keyed by tracker repository plus issue number, confirm its mapping and check for an existing PR, assign the issue, verify the assignment and exclusion from its source, create its worktree, then launch the configured agent there. A confirmed open PR ends the task even if draft or checks are not green. A configurable PR-lookup command is proposed to confirm it. Command invocations are executable-plus-argument templates; a small JSON result contract for discovery and PR lookup is proposed, not decided. Do not interpret arbitrary agent output as proof of a PR.

Retain task state even after the issue drops out of discovery. A failed claim, worktree creation, or agent attempt remains visible. Show process liveness, last output, logs, attempts, and any PR URL. The control surface is a local CLI with per-task pause and resume. Pause stops that task's agent, releases its concurrency slot once it has stopped, and leaves its worktree, local state, and GitHub claim intact. The paused task does not re-enter issue discovery or dispatch; other tasks take the freed slot. Once the stopped attempt is accounted for, resume invokes the configured llxprt-code-rs headless command with the same session ID and worktree and a new continuation prompt. The paused state must survive daemon restart. Exact CLI syntax for daemon controls and graceful termination policy are still design details. Silence raises a warning, not an automatic kill. No automatic retries or unassignment.

Persist launch intent, process identity, and attempt logs so daemon restart can reconcile runs before dispatching. Never start two agents for the same task or exceed the configured global limit. If the daemon cannot establish whether an attempt is still running, what it did, or how it ended, put that task on hold and wait; do not launch another turn or silently treat the attempt as finished. Preserve its logs, worktree, claim, and session identity, inspect available process and PR evidence, and surface what is missing for resolution before an explicit resume. A lost exit code during an outage is a possible cause, not an acceptable terminal `outcome unknown` status. Other tasks may proceed when capacity is known to be free. The OS supervision and reconciliation mechanism proposed below is not an agreed decision.

## Decisions Andrew has made

- An open PR linked to the issue is sufficient for v1, including drafts and PRs with checks that are not green. Report checks, but do not make completion depend on them.
- Support issue sources spanning multiple repositories. Initial testing can start with one.
- Provide a local CLI. Support both macOS and Linux; start testing on macOS.
- Tell the LLxprt agent in the launch prompt that the daemon already claimed the issue. Do not change the skill as part of this daemon.
- Per-task pause stops the agent and frees its slot while preserving the GitHub claim and resumable work; per-task resume uses the same llxprt-code-rs session ID and worktree with a new continuation prompt.
- Use llxprt-code-rs as the first agent target, retaining configurable agent commands rather than building an rs-specific daemon.
- If an attempt cannot be accounted for, hold that task, wait for reconciliation, and do not start another turn on it. Treat missing telemetry as a problem to surface and resolve, not as an acceptable task outcome.

## Pause and resume (Andrew's decision)

Pausing issue 10 stops its active agent and frees its slot after the process has actually stopped. The task remains claimed on GitHub and keeps its worktree and resumable agent state. It does not become eligible for automatic dispatch. Other issues can run. After the stopped attempt is accounted for, resuming issue 10 invokes llxprt-code-rs with `--session ID --cwd WORKTREE -p NEW_PROMPT`: it continues from the last completed turn and the files on disk, but does not retain the canceled turn's conversation. If the stop or outcome cannot be verified, hold and wait rather than launch the continuation. The same state distinction should survive a daemon restart. The Rust daemon's agent invocation remains configured rather than hardcoded to llxprt-code-rs; a configured resume invocation must supply the equivalent action for another agent CLI if one is added later.

A short graceful-stop interval before forcing termination is a possible implementation detail, not yet agreed. A slot must not be reused while the agent is still running.

## llxprt-code-rs headless continuation (read-only source evaluation)

Inspected checkout: `/Users/acoliver/projects/llxprt/agent/main/llxprt-code-rs` at `b526a7f7`, not a binary run. Its [CLI](file:///Users/acoliver/projects/llxprt/agent/main/llxprt-code-rs/src/cli.rs) uses `--session ID --cwd WORKTREE -p PROMPT` for headless continuation, rather than a literal `--continue` flag. The same ID reopens the same session. State under the config root (`code-rs-sessions/ID`) is tied to the worktree's resolved path and device/inode. A new turn receives prior **completed** conversation lineage (`src/agent.rs`, `src/session.rs`, `src/session/reserve.rs`).

If the daemon stops an active turn with SIGINT/SIGTERM, its branch remains pending (`src/process.rs`, `tests/turn_deadline.rs`). Repeating the **same prompt** for that turn while its lease is active returns Busy. Crucially, a **different continuation prompt** with the same session ID and worktree can immediately create a sibling turn from the latest completed parent. This is covered by `src/session.rs:486-569` and `tests/session_reservation.rs:472-503`. It keeps the session identity, prior completed conversation, and changed worktree files. It excludes the interrupted turn's prompt and in-flight model/tool transcript from the new model context; only the new continuation prompt represents that unfinished task in the resumed branch. If the interrupted turn was the first turn, there is no earlier completed conversation to reconstruct, though its worktree changes remain. Reclaiming the exact pending branch after lease expiry also restarts that turn rather than continuing mid-round, so the daemon should prefer a distinct continuation prompt and instruct the agent to inspect worktree changes before acting.

**Consequence for this daemon:** Andrew chose rs as the first agent target. Stop the agent, account for its stopped attempt, free its slot once stopped, then run a **different resume prompt** in the same session and worktree when explicitly resumed. If the attempt is not accounted for, hold and wait instead of launching another turn. This continues the implementation with prior completed conversation and on-disk work; it does not pick up the interrupted model/tool round at the same point. Keep session ID, config root, and worktree filesystem identity stable. Configure these arguments rather than hardcode an agent driver. This is source-backed, not runtime-tested; no agent or daemon was built or run.

## PROPOSAL: minimal attempt observability and restart reconciliation (not an agreed decision)

This is a proposed v1 protocol, not authorization to build. One daemon owns task records and worktrees. The local CLI reads the same records. The agent command, claim check and PR lookup are configured; the first agent command is llxprt-code-rs `--session ID --cwd WORKTREE -p PROMPT` with a stable config root.

### What the operator sees

For each issue, `status` should show task state, current attempt ID and lifecycle, latest accounted attempt outcome, PR lookup result and check status, reserved-slot status, last output age, and the latest reason code with its evidence reference. `show TASK` should expose the ordered events, process and worktree identities, stop/exit evidence, and PR lookup details. `logs TASK` should expose the durable per-attempt stdout and stderr. Keep an agent failure visible even if a later PR lookup finds an open PR; show both facts rather than rewriting the attempt outcome. An absent PR after a clean agent exit means the attempt ended without completing the task. It is not a successful issue-to-PR result.

On restart, the daemon reconciles unfinished attempts before dispatch: a verified live supervisor keeps its slot; a durable exit receipt plus verified process-group termination closes the attempt; missing or contradictory evidence holds the issue and reserves capacity unless termination is independently proven. A held issue gets no new turn. When capacity cannot be proven free, do not dispatch into that slot, even if this stops global dispatch. Resolving a missing receipt requires recorded absence evidence, a fresh PR check, and an explicit audited operator action as described below. Never invent an exit code. No automatic retry follows reconciliation.

### Records and proof

- **Task state** is `preparing | running | pause_requested | paused | held | attention | pr_complete`. `held` blocks that task's dispatch pending evidence; `attention` requires an operator decision after a known failure. Neither is a terminal attempt outcome. Keep the task keyed by tracker repository and issue number after it disappears from discovery. A task is `pr_complete` only after a verified open PR and accounting for any launched agent. Never turn an agent's zero exit into PR completion.
- **Attempt lifecycle** is `launch_intended | starting | running | stop_intended | ended | reconciliation_required`. Its separate final accounting is `exit(code) | signal(number) | launch_failed(reason) | telemetry_lost(reason, evidence)`. The last value records loss of the exit receipt after explicit resolution, not an inferred agent exit. An unfinished attempt stays in reconciliation, never a terminal `outcome unknown`. The attempt has a UUID, task key, session ID, worktree resolved path and filesystem identity, command/config revision, prompt kind, timestamps, process identities, and log/receipt paths. Preserve the exact stop reason separately from exit or signal.
- **PR evidence** is `unchecked | open(repo, number, url, head, checked_at) | absent(checked_at) | lookup_error(reason, checked_at)`. Only a successful configured lookup can produce `open` or `absent`. Require an open PR in the mapped code repository with the task's branch as head and an unambiguous reference to the exact tracker repository and issue number. Capture checks as advisory data; draft and red checks still count. Conflicting or incomplete matches need operator attention. Agent output and exit status are never PR evidence.
- **Reason codes** are stable and stage-specific: `claim_failed`, `claim_unverified`, `worktree_failed`, `launch_failed`, `agent_exit_nonzero`, `stop_requested`, `stop_timeout`, `receipt_missing`, `identity_unverified`, `log_write_failed`, `pr_absent`, `pr_lookup_failed`, `pr_ambiguous`, `telemetry_lost`. Each event records code, task, attempt if any, timestamp, command stage, bounded stderr or OS error, and available evidence. Display the latest code and last output age in `status`; preserve the ordered history and full stdout/stderr streams in `show` and `logs`. Silence warns but never stops an agent by itself.

### Persist before acting

Use a single local SQLite store for task, attempt and ordered event records, and a private append-only stdout/stderr pair per attempt. Commit an intent before each assignment, worktree creation, agent launch or stop signal; persist the target, attempt UUID and chosen action. Verify a claim with a separate configured read: the issue is assigned and no longer passes its configured Project/source eligibility check because it has an assignee. Do not remove its ready marker. If assignment or worktree creation has an ambiguous result, inspect it instead of repeating the operation. A failed durable write prohibits the next side effect. The agent's stdout and stderr flow to files as the attempt runs; record byte counts and last-output time. A missing or failed log stream is reported and holds the task rather than silently discarding evidence. Restrict file permissions and exclude secrets from status/events; agent output can itself contain secrets, so local access to logs must be restricted.

Start each agent through a detached supervisor mode of the same daemon executable. The supervisor stays alive across a daemon restart, owns a child process group, drains both log streams and waits for the child. Before child execution, durably register supervisor identity, then gated child PID, start identity and group identity; release the gate only after registration. A failure to register leaves the child unable to execute the agent. Write the final receipt to a temporary file, sync it, atomically rename it and sync its directory before supervisor exit. The receipt names attempt UUID, child identity, exit code or signal, end time and observed log counts. Treat a partial receipt as missing. Store a boot discriminator with PID and OS start identity; require a live supervisor handshake identifying the UUID or matching OS process identity before signaling. A bare PID or group number is never enough to send a signal.

### Reconcile before dispatch

At startup, lock the local store and reconcile all unfinished intents and reserved slots before launching work. Match a valid receipt to its attempt and check that the registered group has stopped; recheck PR via the configured lookup, then derive task state. Reattach to a verified live supervisor. For a launch intent without proof of a started agent, inspect supervisor/child identities and worktree before deciding that no agent ran; an ambiguous case becomes `held`. If the supervisor died without a receipt, retain the hold and inspect group membership. Compare boot and process start identities on macOS and Linux to avoid treating a reused PID as the agent. Do not infer a result from a missing PID, a quiet log, or a successful command invocation. Retry failed evidence reads on operator `reconcile TASK`, without launching another turn.

Persist `pause TASK` as stop intent before signaling the verified group. Default to SIGINT, then bounded configurable SIGTERM and SIGKILL escalation; log each signal and its reason. Stop confirmation requires a receipt or the explicit telemetry-loss resolution below, plus verified group termination. Keep the claim, worktree, session ID and logs. If stopped with a confirmed absent PR, set `paused`; if PR lookup fails or process evidence is incomplete, set `held`. A PR detected while an agent is live causes a stop request; completion waits for stop accounting. `resume TASK` is operator-only, requires confirmed stop, resolved attempt accounting, successful fresh PR absence check, the same worktree filesystem identity and session/config root, and a free slot. Use a new attempt UUID and a **different** continuation prompt on the same rs session/worktree; instruct inspection of files left by the canceled turn. Prior completed conversation survives; canceled turn conversation does not. No auto retries, reviews, merges or automatic unclaiming.

Count intent-to-launch and live or unverified groups as reserved capacity even across daemon restarts. Release a slot only with verified termination of the registered group, even if a receipt exists; a held task with proven group absence holds no slot but still cannot start a new turn. Dispatch other tasks only from proven-free slots. If all slots remain uncertain, stop dispatch globally while retaining per-task holds. No two attempts may run for one task.

If a receipt is irretrievably lost, `resolve-telemetry-loss TASK --reason ...` requires an operator, verified absence of the registered group (and any tracked descendants), a successful fresh PR lookup, and inspection of claim and worktree. Record evidence, actor, reason and timestamp as `telemetry_lost`; preserve actual exit status as unavailable. A confirmed PR can then complete the task. Otherwise keep `attention`, or `paused` if the stop intent and stop are proven, until an explicit `resume TASK`. If liveness or PR evidence remains unavailable, keep `held` and forbid forced resume. `status`, `show TASK`, `logs TASK [--attempt ID]` and `reconcile TASK` expose reasons and evidence; no `outcome unknown` terminal state exists.

### Limits and tests before implementation

macOS and Linux do not retain a waitable child exit code after its waiting supervisor and durable receipt are lost. PID and process-group reuse require identity checks; a daemonizing agent that escapes its group cannot be cleared merely because its original group is gone. Keep that task held until independent absence evidence is available. GitHub outages prevent fresh PR verification. The rs continuation contract above is source-backed, not end-to-end tested. Test first: zero/nonzero/signaled exits against open/absent/failed PR lookup (including draft/red checks); pause escalation and same-session new-prompt resume; daemon crashes before child release, during execution and before receipt ingestion; supervisor death, missing receipt, PID reuse and group escape; partial worktree/ambiguous claim, log or SQLite write failure, lost telemetry resolution, and restart with uncertain capacity. Assert no new turn on a held task and no capacity reuse without verified termination. No tests or implementation were performed here.
