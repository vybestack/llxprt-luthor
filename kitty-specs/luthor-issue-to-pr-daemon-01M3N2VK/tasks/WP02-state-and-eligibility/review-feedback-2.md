# WP02 review verdict: changes requested

WP02 cannot yet provide safe read-only candidate discovery. All 44 existing Rust tests and `cargo clippy --offline --all-targets -- -D warnings` pass in the lane worktree, but the following production cases violate WP02's own selection, security, and evidence contracts. No assignment, worktree, agent supervision, or PR-completion behavior is being requested here; those belong to WP03/WP04. There is no `contracts/` artifact for this mission.

1. **The configured live Project cannot be enumerated.** `src/github/project.rs:274-307` returns an error on every Project item whose content type is not `Issue`; `src/eligibility.rs:47` aborts selection for the whole Project. WP01's completed read-only Project #8 traversal under `tmp/wp01-pagination/` contains 1,160 `Issue` items and two `PullRequest` items, at `page-02.json` (`PVTI_lADODYHhhs4BOTgmzgld6sg`) and `page-08.json` (`PVTI_lADODYHhhs4BOTgmzgzpKr8`). Reproduce: `jq -r '.data.node.items.nodes[] | .content.__typename // "null"' tmp/wp01-pagination/page-*.json | sort | uniq -c` from the lane worktree. The existing `tests/project.rs::rejects_non_issue_project_items_with_item_identity` confirms that this input errors; the live Project necessarily reaches the first PR before successful exhaustion. Parse and skip ordinary non-issue Project content while continuing to reject malformed/missing issue identity, incomplete pagination, and failed reads. Add a mixed Issue/PR page integration test that still selects the eligible Issue after full enumeration. The real GraphQL field query itself succeeds; a read-only live query returned the expected Issue and field shapes.

2. **Credential-bearing argv passes validation and can be stored as effective configuration.** `src/config.rs:252-271,320-331` recognizes a short denylist of names, but accepts the separate option/value pair `--auth FAKE_CREDENTIAL_VALUE`; `src/state.rs:182-190` serializes both validated command templates verbatim into SQLite selection evidence. I supplied this pair in ignored `tmp/wp02-review-probe/config.json` and ran `./target/debug/luthor discover --config tmp/wp02-review-probe/config.json`; it reached `Project enumeration failed`, rather than returning `invalid configuration`. The probe uses a dummy string, not a credential. This violates the WP02 nonsecret configuration and persisted-diagnostics requirements. Make credential-bearing options and associated values impossible in this template contract (including separate argv values), or define a verified allowed nonsecret argv surface; add a config validation test and a persistence test asserting that such a configuration cannot become task evidence. Do not print rejected values.

3. **Selection evidence can claim a mapping that the validated effective config does not contain.** `src/state.rs:157-190` calls `config.validate()` but never validates that `candidate.source`, `candidate.mapping`, repository identity, and requested revision agree with that config before committing the task and its `SelectionEvidence`. This happens in an existing passing test: `tests/state.rs:239-248` calls `create_task` with `candidate("r", "i1", "repo", 1)` and `config()` whose only tracker mapping is `org/tracker` (`tests/state.rs:165-181`). The stored record can therefore attest to a selected source/mapping unrelated to the persisted effective configuration. Validate this relationship at the task creation boundary, or derive the stored selection only from the validated config and selected item; reject mismatches atomically. Add a negative test that checks no task or selection evidence is committed.

4. **`discover` mutates and exclusively locks state before any Project read.** `src/main.rs:39-41` opens `StateStore` in a supposedly read-only discovery command; `src/state.rs:83-154` creates the directory, changes permissions, acquires the coordinator's exclusive lock, creates/migrates SQLite, and persists capacity. The same failed read-only probe created `tmp/wp02-review-probe/state/coordinator.lock` and `state.sqlite3` even though Project enumeration failed. This also prevents discovery beside a running coordinator, and a capacity mismatch can block a read-only Project inspection. Remove mutable state opening from `discover`, or provide a genuinely non-mutating read path if state data is needed. Test that discovery leaves a fresh state directory absent and can run while the coordinator holds its lock. This does not ask for WP03's `status`, `show`, `logs`, `pause`, `resume`, or `reconcile` controls.

5. **The published JSON example does not load.** `dev-docs/config-and-state.md:13` omits `push_remote`, `allowed_pr_head_repository`, and `allowed_pr_author` from its mapping, although `src/config.rs:44-53` requires all three. Make the example pass `Config::from_json` and add an example round-trip test so documentation matches the contract.
