# WP03 review: reject

The existing tests pass (`cargo test --all-targets --quiet`), but the following acceptance requirements remain unmet. This feedback covers the current checkout. No production code was changed during review.

1. **A live agent has no durable child identity until it exits.** `src/supervisor.rs:495-506` launches the worker immediately after the supervisor reads the release byte and resolves its identity only after `spawn`; `src/supervisor.rs:550-568` first persists the child PID/start/boot information in the final receipt. `src/supervisor.rs:974-1002` persists the supervisor identity, then sends release, then writes `gate_sent`. If the supervisor crashes after spawning an agent but before issuing a receipt, the stored identity is only the *supervisor*, while the agent group can remain alive. `request_stop` at `src/supervisor.rs:343-374` cannot connect to that dead supervisor, and `reconcile_attempt` at `src/supervisor.rs:669-691` stops on a missing receipt before it can independently account for a known child. The slot stays reserved, which prevents unsafe reuse, but the agent is no longer identifiable or controllable through Luthor. A transient failure of `identity(pid)` immediately after `spawn` has the same effect and drops the unreaped live child. Persist verified child/group identities and a release handshake at the correct gate boundary; on failed registration, close the gate and reap the child. Provide a deterministic test that kills the supervisor after worker spawn and before receipt and demonstrates independent identification/stop or an explicit safely accounted recovery.

2. **A persisted release can launch a worker while its successful receipt is permanently unreconcilable.** `src/supervisor.rs:995-1002` writes the release byte before inserting `gate_sent`; `src/supervisor.rs:708-725` requires `gate_sent`, and `src/state.rs:965-973` also requires it to release a reservation. Crash or SQLite failure between those operations leaves a legitimate worker, logs and receipt, but every subsequent reconciliation holds the slot forever. This is not the specified restart handshake. Inject failure on the `gate_sent` write after releasing the byte, restart, and verify that a valid receipt plus independently verified group absence can be reconciled without fabricating evidence or launching a duplicate. Record a durable release decision and handshake that do not depend on a post-release coordinator write.

3. **The same-session resume guarantee is not enforced.** `src/supervisor.rs:49-57` persists no environment or session-root identity; `src/supervisor.rs:161-224` checks the session ID and worktree but never checks HOME/XDG or the rs session/config root. `src/supervisor.rs:495-502` spawns the agent with whatever environment the current invoking process inherited. Reproduce by starting under HOME=A, stopping and reconciling, then explicitly resuming under HOME=B with the same state root: the resumed agent is sent the same `--session` but resolves a different on-disk session. Persist the root-defining environment identity at initial dispatch and require the identical root on resume (or launch with the captured root); add a two-process integration test with different HOME/XDG values that rejects the second attempt before reserving or spawning.

4. **The required issue-link/head/base launch instruction is optional.** `src/config.rs:52-56,72-83` accepts arbitrary argument templates; `src/supervisor.rs:132-145` only requires a nonempty prompt and `--session`/`--cwd`. For example, `tests/coordinator.rs:77-89` launches successfully with `-p "start {task.issue_url}"`, which does not supply the mapped code repository, base, authorized head, the exact `Tracker-Issue: URL` PR-body line, or the instruction not to reassign an already claimed issue. Since the WP's pre-claim PR lookup (`src/github/pull_request.rs:157-164`) keys on that line and the agent owns PR creation, this omission makes the expected proof non-deterministic. Construct and persist the mandatory launch instructions from the selected task/mapping, leaving only optional task-specific template content configurable. Add a test asserting the prompt includes the exact tracker line, mapped base/head/repository, and assignment prohibition before launch.

5. **Pause frees the SQLite reservation but new-task admission still counts the paused task.** `src/state.rs:1000-1005` sets `paused` and releases its reservation after verified stop; `src/state.rs:505-525` nevertheless treats every task whose state is not the never-produced `completed` as consuming capacity. With capacity 1, after a verified pause, dispatching an unrelated issue fails `ensure_dispatch_capacity` even though `reservation_count()` is zero; `tests/coordinator.rs:694-722` currently asserts the behavior. This contradicts WP03's requirement for a paused task to free capacity while other tasks proceed. Preserve the no-automatic-replacement rule for held uncertain work separately from slots available after verified pause. Add a test that pauses task A, verifies its group exited and reservation released, and dispatches task B without retrying A or overcommitting live agents.

The mission spec and architecture do not promise cross-actor atomic GitHub assignment; this review does not request such a guarantee. The existing PR lookup is a pre-dispatch exclusion check, not completion proof, which remains WP04 scope. There is no `contracts/` artifact for this mission. WP04 and WP05 depend on correcting these WP03 guarantees before accepting the process and PR-provenance chain.
